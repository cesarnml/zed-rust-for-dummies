## What this is

A study guide for one specific piece of work: **per-window theme overrides in
[Zed](https://github.com/zed-industries/zed)** — letting each editor window use
its own theme so you can tell a production checkout from a staging one at a glance.

The branch is `cesar/per-window-theme`. It touches **307 files, +4,701 / −3,078
lines**. Roughly 2,900 of those lines are one mechanical rewrite repeated ~1,800
times. The remaining ~200 lines are the actual feature.

The site is written for someone who is fluent in TypeScript and functional
programming and is **not** yet fluent in Rust. Every Rust and GPUI concept the
diff depends on is explained from scratch, in the order the diff needs it.

## The shortest possible version

Zed's theme is a single global value. Every part of the UI asked one question —
*"what's the theme?"* — and got one answer. To let one window differ from another,
every part of the UI has to ask a slightly different question: *"what's the theme
**for this window**?"*

The feature is ~200 lines. Making the question un-askable the old way is ~2,900.

That trade — deleting the old accessor so the compiler enumerates all 1,800 call
sites, instead of hand-auditing them — is the whole argument of the PR, and it is
the thing you need to be able to defend without notes.
